# Functional & Technical Requirements Specification
## Component: Cost Optimization Telemetry Agent
**Integration Target:** ClickHouse MCP (`mcp-clickhouse`)  
**Project:** Agentic Cinema Cost Optimization Pipeline  

---

### 1. Purpose & Scope
The Telemetry Agent is an autonomous monitoring daemon responsible for capturing empirical generation metrics during user video creation sessions. While the upstream Cost Optimization Agent provides preliminary model recommendations and cost estimates using Google Gemini, the Parallel API, and a deterministic script, the Telemetry Agent records ground-truth performance. It monitors user regeneration loops, aggregates total realized costs, logs acceptance outcomes, and persists this structured telemetry directly to a ClickHouse database via the Model Context Protocol (MCP).

---

### 2. Functional Requirements (FR)

*   **FR-1: Session Lifecycle Initialization**
    *   **FR-1.1:** Intercept the active `session_id` generated by the application orchestrator upon initial query submission.
    *   **FR-1.2:** Ingest and buffer session metadata prior to generation: raw `prompt_text`, user-selected `suggested_model`, and quoted `base_api_cost`.
    *   **FR-1.3:** Initialize in-memory counters: `total_rerun_count = 0` and `total_session_cost = base_api_cost`.

*   **FR-2: Iteration & Rejection Tracking**
    *   **FR-2.1:** Listen for generation rejection events (e.g., user selects "Regenerate", "Retry", or modifies prompt adjustments within the active session).
    *   **FR-2.2:** For every rejection event, increment `total_rerun_count` by 1.
    *   **FR-2.3:** Add the incremental API cost of each subsequent generation to `total_session_cost`.
    *   **FR-2.4:** Maintain active session buffer in memory until a terminal event occurs.

*   **FR-3: Acceptance & Abandonment Detection**
    *   **FR-3.1:** **Positive Terminal Event:** When the user explicitly accepts or downloads the generated video, set `user_accepted = 1`.
    *   **FR-3.2:** **Negative Terminal Event:** If the user closes the session, cancels, or the session exceeds a configurable idle timeout (default: 15 minutes) without acceptance, set `user_accepted = 0`.
    *   **FR-3.3:** Lock the state of `total_session_cost` and `total_rerun_count` upon any terminal event.

*   **FR-4: ClickHouse MCP Ingestion (Egress)**
    *   **FR-4.1:** Establish a JSON-RPC / stdio connection to the local or remote `mcp-clickhouse` server instance.
    *   **FR-4.2:** On terminal event lock, map buffered session attributes into an executable SQL `INSERT` statement.
    *   **FR-4.3:** Dispatch the query via the MCP query execution tool to append the record to the `generation_telemetry` table.
    *   **FR-4.4:** Verify write acknowledgment from the MCP server; log errors locally if the database is unreachable without interrupting user flow.

### 3. Data Dictionary & Storage Specification

The Telemetry Agent must ensure the target ClickHouse table exists via MCP before running inserts:

```sql
CREATE TABLE IF NOT EXISTS generation_telemetry (
    session_id UUID,
    prompt_text String,
    suggested_model LowCardinality(String),
    base_api_cost Float32,
    total_rerun_count Int32,
    total_session_cost Float32,
    user_accepted UInt8,
    created_at DateTime DEFAULT now()
) ENGINE = MergeTree()
ORDER BY (suggested_model, created_at);
